# Pylolith v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Pylolith v0.1, an in-process, API-aware web application firewall library for Go JSON APIs with `net/http` and Fiber v2 middleware, proven against a 107-attack / 32+-legitimate-request corpus.

**Architecture:** One core Go module (stdlib + libinjection-go) with internal packages for normalization, protocol checks, detectors, route policies and the engine pipeline; the root package exposes the public API by type aliases. Adapters: `httpwaf` (stdlib, in the core module) and `adapters/fiberv2` (its own Go module). The corpus test is the acceptance gate.

**Tech Stack:** Go 1.25, `github.com/corazawaf/libinjection-go` v0.3.7 (BSD-3-Clause), `github.com/gofiber/fiber/v2` v2.52.16 (adapter module only), `log/slog`, `testing` (unit, fuzz, bench).

**Spec:** `docs/superpowers/specs/2026-11-24-pylolith-v0.1-design.md` (read it, especially sections 5, 6 and 9).

## Global Constraints

- Module path `github.com/ergasterion-dev/pylolith`; Go directive `go 1.25`.
- Core module dependencies: standard library + `github.com/corazawaf/libinjection-go` only. Fiber only in `adapters/fiberv2/go.mod` (module `github.com/ergasterion-dev/pylolith/adapters/fiberv2`).
- License Apache-2.0; `NOTICE` credits libinjection (BSD-3-Clause) and OWASP CRS (Apache-2.0) for adapted patterns. Never copy code from GPL/AGPL projects.
- No GitHub Actions, no `.github/workflows/` (owner's rule). CI = `make ci` + `scripts/pre-commit`.
- Commit straight to `main` and `git push origin main` after every commit (owner's rule). Conventional Commits.
- Rule IDs: `PYL-<CATEGORY>-<NNN>`, stable once published.
- No panic may escape `Inspect` or a middleware; `FailOpen` default true.
- Never log or return full request values: snippets are redacted and at most 64 bytes.
- Defaults: allowed methods `GET HEAD POST PUT PATCH DELETE OPTIONS`; allowed content types `application/json`, `application/x-www-form-urlencoded`, `multipart/form-data`; MaxBodyBytes 1 MiB; MaxDepth 32; MaxFields 1000; MaxValueLen 8192; UnknownRoute monitor; UnknownFields monitor; Mode enforce.
- Default rule actions: every attack detector, scanner UA and probe-path rule = block; unknown route, over-long value, malformed JSON = monitor; schema mismatch on a declared field = block.
- Acceptance gates (corpus, enforce mode, no exclusions): generic config blocked >= 95/107 and false positives 0; API-aware config blocked >= 99/107 and false positives 0.
- Performance: typical request (corpus legit set) p99 < 50 µs on one core.

## Review Focus

- Deep or huge JSON bodies (nesting 10,000 levels, 100k fields, 10 MiB): `Inspect` returns within bounds with a monitor match, never panics or recurses unboundedly. Test in Task 2 (`TestWalkJSONLimits`) and Task 8 (`TestInspectHugeBody`).
- Malformed or non-UTF-8 JSON with `Content-Type: application/json`: no panic; one monitor match `PYL-PROTO-020`; raw body still text-scanned once as a single value. Test in Task 8 (`TestInspectMalformedJSON`).
- Concurrent use of one `*Firewall` from many goroutines: race-free and identical decisions. Test in Task 8 (`TestInspectConcurrent`, run under `-race`).
- Multipart uploads (images): file parts are never text-scanned (binary would false-positive); only non-file form fields are. Test in Task 8 (`TestInspectMultipartFileNotScanned`).
- The next handler must still see the full, unmodified body after the middleware read it. Tests in Task 10 (`TestMiddlewareBodyRestored`) and Task 11 (`TestFiberBodyIntact`).

### Task 2: Normalization (decode, JSON walk, query/form/cookies, multipart)

**Files:**
- Create: `internal/normalize/decode.go`, `json.go`, `query.go`, `multipart.go`
- Test: `internal/normalize/normalize_test.go`

**Interfaces:**
- Consumes: `model.Limits`.
- Produces:
  - `func DecodeValue(s string) (decoded string, doubleEncoded bool)`: one percent-decoding pass tolerant of invalid escapes (a stray `%` stays literal: `"50% off"` -> `"50% off"`, false); `+` stays `+`; doubleEncoded is true when the decoded string still contains a valid `%XX` escape of `%`, `.`, `/`, `\`, `<`, `'`, `"`, NUL, CR or LF.
  - `type KV struct { Key, Value string }`
  - `func ParseQuery(raw string) []KV` (order preserved, tolerant: never errors; `+` -> space in query values, per form encoding)
  - `func ParseForm(body []byte) []KV`
  - `func ParseCookies(h http.Header) []KV`
  - `type JSONValue struct { Path, Key, Value string; IsString bool }` (Path: dotted, arrays as `[]`, e.g. `address.line1`, `items[].sku`; Key: the last object key, "" for array elements)
  - `var ErrLimit = errors.New("normalize: limit exceeded")`, `var ErrMalformed = errors.New("normalize: malformed JSON")`
  - `func WalkJSON(body []byte, lim model.Limits, fn func(JSONValue)) error`: streaming `encoding/json.Decoder` with `UseNumber`; calls fn for every string, number, bool value and once per object key (Value = key, IsString true, Path ends with the key); stops with ErrLimit past MaxDepth or MaxFields; ErrMalformed on syntax error (values already emitted stay emitted).
  - `type Part struct { Name string; IsFile bool; Value string }`; `func ParseMultipart(body []byte, contentType string, lim model.Limits) ([]Part, error)`: file parts (have a filename) are returned with IsFile true and empty Value.
